## 三、核实确认的既有优势（保持，勿回退）

1. **构建期冻结 + 运行期不可变**：`AppBuilder` 多步校验，资源经 `ToolsBuilder` 显式所有权，无资源类全局单例（仅 `OnceLock` 用于 schemars schema 缓存，非资源持有）。
2. **TableQuery 安全边界完整**：字段/排序权限校验、条件树深度上限 32、LIKE 模式长度上限、IN 列表 500 上限、空逻辑组拒绝（防 `WHERE (1=1)` 全表写绕过）、字段类型与值类型校验、标识符三层防护、分页上限 100。
3. **JWT keyring**：算法白名单、稳定 kid（缺失/未知即拒）、8 把密钥上限、最小 HMAC 32 字节、签发/验证双侧 alg 比对。
4. **撤销链路全路径 fail-close**（含专项回归测试）。
5. **yang-system 认证纵深**：等时密码校验（`verify_or_dummy` 防枚举）、规范化限流、Refresh Cookie Host-only+HttpOnly+SameSite=Strict、变更类请求 Same-Origin 校验（`Sec-Fetch-Site` + Origin/Referer 与 Host 比对）、config `deny_unknown_fields` + Debug 脱敏、非 root 容器（`USER yang`）、带 readiness gate 与共享关闭预算的启动/停机序列。

## 四、两条评审的核心判断（经核实维持）

1. **lib_yang 的成熟度上限不在功能，而在公共 API 的「误用代价」**：框架层面的安全设计（TableQuery 边界、fail-close、类型化引用）质量高于一般个人项目，但 `query(&str)`/`create_table`/`parse_token_unsafe` 等 escape hatch 仍允许调用方绕过安全保证。这是从个人高级项目进入成熟工程最关键的收口点。
2. **两份评审共享的过时基线问题**：文档一整体基于更早版本（crates.io 发布视角），其「安全隐患」章节（Record panic、SQL 注入、fail-open、无分页上限）在 2026-09 当前基线**全部不成立**；文档二声明基线 2026-09-10，但 `deny.toml` 豁免等项已被后续提交修复。**引用这两份文档时必须标注时效性**，否则会按已修复的问题返工。
